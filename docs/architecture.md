# Architecture

neverfired is one Go program in `plugin/scripts`, using only the standard library, so the installed plugin builds with `go build` and no module download. YAML is read with go.yaml.in/yaml/v3 v3.0.4, copied into `yaml_*.go` with the package renamed (Apache 2.0 and MIT, see `YAML_LICENSE` and `YAML_NOTICE`). It uses the v3 node API, so every finding has a line number.

## Flow

1. **Test files (`load.go`, `loadTestFile`).** Each file is read whole and refused if it is missing, empty, binary, not valid UTF-8, missing its final newline, the output of a failed command (promtool, go, helm, kubectl, jsonnet, make), more than one YAML document, or not a mapping. Fields are checked the way promtool checks them: unknown fields are refused unless `--ignore-unknown-fields` is set. Durations use the Prometheus syntax (`1h30m`, `0`). Each input series is parsed as a series selector, and its `values` string is read in promtool's expanding notation (`1+2x10`, `_x3`, `stale`, native histograms in `{{ }}`) to find the first real sample. A test file with no tests, a test group with no test cases, and a test case missing a required field are refused, since promtool would pass the first two without checking anything and the third often means the file is cut off.
2. **Rule files (`loadRuleFile`).** `rule_files` entries are globbed relative to the test file, as promtool does. Rule files are read with the same checks. Every `expr` is parsed with the PromQL parser in `promql.go`; an expression that doesn't parse is refused. `--rules` files may also be PrometheusRule objects (one or more documents); their `spec.groups` are read.
3. **PromQL (`promql.go`).** A hand-written lexer and precedence-climbing parser for Prometheus 3 syntax: selectors with all matcher types and quoted UTF-8 names, functions (checked against Prometheus's function list), aggregations with `by`/`without` in either position, binary operators with `bool`, `on`/`ignoring`, `group_left`/`group_right` and the experimental `fill` modifiers, the histogram trim operators `</` and `>/`, ranges, subqueries, `offset`, `@`, `smoothed`, `anchored` and duration expressions. It keeps what the checks need: each selector's matchers, whether `offset` or `@` applies to it, and the expression's shape. It doesn't type-check.
4. **Can the expression return anything? (`check.go`, `feedCtx.empty`).** For a test group and a time `t`, a selector is *starved* when no input series with a real sample at or before `t` matches it (any time if `offset` or `@` applies), and no recording rule that could produce its name is itself fed. Emptiness then follows the operators: aggregations and most functions are empty when their series argument is; `absent`, `absent_over_time`, `vector`, `time`, `scalar` and `pi` never are; `info` follows its first argument; `and` and arithmetic are empty when either side is; `or` and `fill` only when both are; `unless` when its left side is. Anything unsure counts as not empty, so a claim of "returns nothing" is always true; `tests/enginecheck` checks this against the Prometheus engine. Each starved selector is classed as `labels` (series with that metric name exist with other labels), `late` (matching series start after `t`) or `absent` (no series with that name).
5. **Checks (`checkTestFile`, `analyze`).** For each `alert_rule_test` case: an alertname with no rule is NF102. A case with `exp_alerts` counts the alert as shown firing, and its expected labels and annotations are compared with the rule's static ones (NF106). A case with no `exp_alerts` is a quiet check; it is empty for a rule when `eval_time` is before the rule's `for` (unless the group checks the alert again later) or the expression is starved. When every rule with that name is empty, the case is NF103, NF104 or NF107 by reason. `promql_expr_test` cases with no `exp_samples` get NF105 or NF108 the same way. Then each alert is classed as shown firing, quiet only, untested, or not loaded, with copies in `--rules` files matched by name and compared by normalized expression and `for` (NF203, NF204).
6. **Report (`neverfired.go`).** Findings sorted by level then file and line, a coverage table, and a summary line. Exit 0, 1 by `--fail-on`, and 2 for every refusal, with nothing on stdout.

## How it is checked

- `plugin/scripts/neverfired_test.go`: parser, durations, value notation, and emptiness rules.
- `tests/`: the built binary on the examples, every `--fail-on` value, JSON output, a matrix of broken inputs for each of the three inputs with the others real, every byte prefix of both healthy example files, the README's commands and the installed plugin.
- `tests/enginecheck`: a separate module that takes the 1,688 instant queries in Prometheus's engine tests, writes promtool test files for each with all the series and with each metric name removed in turn, runs neverfired on them, and evaluates the same queries with the Prometheus engine. Every expression neverfired calls empty must be empty in the engine.
